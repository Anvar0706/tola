# TLS-721 TOKENIZED EXTERNAL ASSET SPECIFICATION

**Status:** CANONICAL SPECIFICATION  
**Scope:** Interface and Architecture for Tokenized External Assets (TLS-721) on TOLA Network

---

## 1. Overview

**TLS-721** is the token standard on TOLA Network for representing on-chain tokenized assets that originate on external platforms (e.g., PaxtaGram, Telegram, X, Discord).

> [!IMPORTANT]
> **ARCHITECTURAL SOURCE OF TRUTH**
> TOLA Network does NOT operate a native username registry, does NOT create native messenger gifts, does NOT issue Gifts Numbers, and does NOT maintain profile badge registries. All digital collectibles, usernames, and assets represented on TOLA originate exclusively on **external platforms** and are tokenized via independent third-party tokenization applications into TLS-721 tokens.

Reference Smart Contract: [`contracts/TolaExternalAssetToken.sol`](../../contracts/TolaExternalAssetToken.sol)

---

## 2. Token Architecture & Decoupled Ownership

TLS-721 enforces complete cryptographic decoupling between TOLA on-chain ownership and external platform database state:

```
┌──────────────────────────────────────────────┐
│           External Platform DB               │
│  - Handle / Item ID / Ownership Record       │
└──────────────────────┬───────────────────────┘
                       │
                       ▼ Third-Party Verification
┌──────────────────────────────────────────────┐
│         Independent Attestation Service       │
│  - ECDSA Secp256k1 Signed Attestation        │
└──────────────────────┬───────────────────────┘
                       │
                       ▼ Mint Transaction
┌──────────────────────────────────────────────┐
│          TLS-721 On-Chain Token              │
│  - tokenId: uint256                          │
│  - canonicalId: bytes32                      │
│  - sourcePlatform: string                    │
│  - assetType: uint8                          │
│  - externalAssetId: string                   │
│  - verifier: address                         │
│  - metadataUri: string (IPFS / Arweave CID)  │
└──────────────────────────────────────────────┘
```

### Key Invariant:
Ownership of a TLS-721 External Asset token represents blockchain ownership of the representation on TOLA. It does NOT automatically mutate or synchronize with the external platform's internal database.

## 3. Core Interface Definition (`ITolaExternalAssetToken`)

```solidity
interface ITolaExternalAssetToken {
    enum ExternalAssetType {
        MESSENGER_USERNAME,  // 0 -> 1 in protocol
        MESSENGER_NUMBER,    // 1 -> 2 in protocol
        MESSENGER_GIFT,      // 2 -> 3 in protocol
        MESSENGER_BADGE,     // 3 -> 4 in protocol
        SOCIAL_USERNAME,     // 4 -> 5 in protocol
        SOCIAL_NUMBER,       // 5 -> 6 in protocol
        DIGITAL_COLLECTIBLE, // 6 -> 7 in protocol
        OTHER_EXTERNAL_ASSET // 7 -> 8 in protocol
    }

    struct ExternalAssetRecord {
        uint256 tokenId;
        bytes32 canonicalId;
        string sourcePlatform;
        uint8 assetType;
        string externalAssetId;
        string metadataUri;
        address verifier;
        uint64 mintedAt;
    }

    event ExternalAssetMinted(
        uint256 indexed tokenId,
        bytes32 indexed canonicalId,
        address indexed owner,
        string sourcePlatform,
        uint8 assetType,
        string externalAssetId,
        address verifier
    );

    event Transfer(address indexed from, address indexed to, uint256 indexed tokenId);
    event Approval(address indexed owner, address indexed approved, uint256 indexed tokenId);
    event ApprovalForAll(address indexed owner, address indexed operator, bool approved);
    event VerifierAuthorizationUpdated(address indexed verifier, bool authorized);

    function mintWithAttestation(
        uint256 nonce,
        uint64 expiresAt,
        string calldata sourcePlatform,
        uint8 assetType,
        string calldata externalAssetId,
        string calldata metadataUri,
        bytes calldata signature
    ) external returns (uint256 tokenId);

    function canonicalIdToToken(bytes32 canonicalId) external view returns (uint256);
    function externalAssets(uint256 tokenId) external view returns (ExternalAssetRecord memory);
    function ownerOf(uint256 tokenId) external view returns (address);
    function balanceOf(address owner) external view returns (uint256);
}
```

---

## 4. Replay & Duplicate Mint Defenses

1. **Replay Defense:** Attestations include `nonce`, `chainId`, `destinationWallet`, and `expiresAt`. Upon successful minting, the attestation hash is permanently marked as used.
2. **Duplicate Mint Prevention:** The smart contract maps `canonicalId -> tokenId`. Any subsequent attempt to mint the same canonical asset is rejected with `AssetAlreadyTokenized`.
